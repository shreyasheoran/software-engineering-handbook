# Release checklist

## Scope

- Release/version:
- Commit/tag:
- Date:
- Owner:

## Documentation

- [ ] README claims reconcile with code and deployment.
- [ ] Requirements and acceptance criteria are complete.
- [ ] Architecture and contracts reflect implementation.
- [ ] ADRs and consequence trade-offs are current.
- [ ] Threat model is reviewed.
- [ ] Runbooks cover release, rollback and recovery.
- [ ] Synthetic-data and privacy constraints are unchanged or reviewed.

## Quality

- [ ] Clean build passes.
- [ ] Relevant unit, integration and end-to-end tests pass.
- [ ] Accessibility checks pass.
- [ ] Security checks pass.
- [ ] Dependency and license review passes.

## Evidence

- [ ] Commit and environment recorded.
- [ ] Benchmark evidence is reproducible and disclosed.
- [ ] Screenshots match the released build.
- [ ] Unsupported claims removed or qualified.

## Deployment

- [ ] Smoke checks pass.
- [ ] Assets return without missing resources.
- [ ] Rollback is prepared.
- [ ] Monitoring and alert state verified.

## Exceptions

List waived checks with reason, owner, risk and expiry date. Waivers must not be silently converted into public claims.
